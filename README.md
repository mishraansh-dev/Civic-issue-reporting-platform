## 1. Project Overview

CivicWatch is a full-stack web application that allows citizens to report local civic issues (damaged roads, water leaks, power outages, garbage overflow, etc.) to their municipal authority. Authority users can view all reports, filter/search them, update their status, and see them visualised on an interactive map and charts.

The project was built in two phases:

- **Phase 1** — Core functionality + premium SaaS-quality UI redesign
- **Phase 2** — Camera-first 4-step report wizard, interactive Leaflet maps, Recharts analytics, AI-ready service architecture

---

## 2. Problem Statement

Citizens often have no efficient way to report local civic problems to municipal authorities. Traditional channels (phone, paper forms) are slow, opaque, and provide no feedback loop. CivicWatch solves this with a digital platform offering real-time status tracking for citizens and a structured operations dashboard for authorities.

## 4. Database Architecture

**Database:** MongoDB, running locally  
**Connection string (from `backend/.env`):** `mongodb://127.0.0.1:27017/civic-issues`  
**ORM/ODM:** Mongoose  
**Connection established in:** `backend/config/db.js`  
**Atlas:** Not configured. This is a local MongoDB instance.

### Collections

#### `users` — defined in `backend/models/User.js`

| Field | Type | Constraints |
|---|---|---|
| `email` | String | Required, unique, lowercase, trimmed, regex validated |
| `password` | String | Required, min 6 chars; bcrypt-hashed (salt 12) via pre-save hook; excluded from JSON via `toJSON` transform |
| `role` | String | Enum: `'user'` \| `'authority'`; default `'user'` |
| `createdAt` | Date | Auto (timestamps: true) |
| `updatedAt` | Date | Auto (timestamps: true) |

**Security note:** The `password` field is never returned in API responses — the `toJSON` transform deletes it before serialisation.

#### `issues` — defined in `backend/models/Issue.js`

| Field | Type | Constraints |
|---|---|---|
| `title` | String | Required, trimmed, max 100 chars |
| `description` | String | Required, max 1000 chars |
| `category` | String | Required, enum: `Road` \| `Water` \| `Electricity` \| `Garbage` \| `Other` |
| `imageUrl` | String | Optional; stores relative path `/uploads/<filename>` or `null` |
| `locationText` | String | Required, trimmed |
| `latitude` | Number | Optional, `null` if no GPS |
| `longitude` | Number | Optional, `null` if no GPS |
| `status` | String | Enum: `pending` \| `in_progress` \| `resolved`; default `'pending'` |
| `userId` | ObjectId | Required, ref: `User` (populated as `email` in API responses) |
| `createdAt` | Date | Auto |
| `updatedAt` | Date | Auto |

**Indexes:**
- Compound: `{ status: 1, category: 1 }`
- Compound: `{ userId: 1, createdAt: -1 }`
- Single: `{ createdAt: -1 }`

**Relationships:** `Issue.userId` → `User._id` (one-to-many; one user, many issues). There is no separate `Department` or `Authority` model — authority is a role on the `User` model.

## 5. Authentication

**Implementation:** Stateless JWT-based authentication stored in `localStorage`.

### How it works

1. **Signup** (`POST /api/auth/signup`):
   - Validates email + password (min 6 chars)
   - Checks for existing email
   - Creates user with **hardcoded role `'user'`** — the API cannot create `authority` accounts
   - Returns `{ token, user: { id, email, role } }`

2. **Login** (`POST /api/auth/login`):
   - Looks up user by email
   - Compares password with bcrypt hash via `user.comparePassword()`
   - Returns `{ token, user: { id, email, role } }`
   - JWT expiry: **7 days**

3. **Token storage:** JWT stored in `localStorage` as `'token'`; user object stored as `'user'`

4. **Request authentication:** Axios interceptor in `frontend/src/services/api.js` attaches `Authorization: Bearer <token>` to every request automatically

5. **401 handling:** Axios response interceptor clears `localStorage` and redirects to `/login` on any 401 response

6. **Backend verification:** `backend/middleware/authMiddleware.js` — verifies JWT using `process.env.JWT_SECRET`; attaches decoded `{ id, email, role }` to `req.user`

7. **Role-based access:** `backend/middleware/roleMiddleware.js` — checks `req.user.role === 'authority'`; returns 403 for all other roles

8. **Frontend route guards:**
   - `ProtectedRoute` — unauthenticated users redirected to `/login`
   - `AuthorityRoute` — non-authority users redirected to `/dashboard`

9. **Logout:** Clears `localStorage` keys `'token'` and `'user'`; redirects to `/login`

10. **Authority account creation:** Only possible via `backend/seed.js` (`npm run seed`). There is no admin panel or API endpoint for this.

## 8. Backend Details

### Entry Point — `server.js`

1. Loads `.env` via dotenv
2. Calls `connectDB()` (Mongoose connect)
3. Creates Express app + raw HTTP server
4. Calls `initSocket(httpServer)` — Socket.io must be initialised before routes use `getIO()`
5. Ensures `uploads/` directory exists (creates it if not)
6. Registers middleware: CORS, `express.json()`, `express.urlencoded()`
7. Serves `/uploads` as a static directory
8. Mounts routes: `/api/auth`, `/api/issues`
9. `GET /api/health` health check endpoint
10. Global error handler (status 500 fallback)

### File Upload — Multer (in `issue.routes.js`)

- Storage: `multer.diskStorage` → `backend/uploads/`
- Filename: `issue-<timestamp>-<random>.ext`
- File filter: JPEG, JPG, PNG, GIF, WebP only (checks both extension and MIME type)
- Size limit: **5 MB**
- The stored path `/uploads/<filename>` is saved as `imageUrl` in the Issue document
- Images are served statically at `http://localhost:5000/uploads/<filename>`

### Socket.io — `config/socket.js`

- Singleton pattern: `initSocket()` creates the instance; `getIO()` returns it
- CORS allowed for `CLIENT_URL`
- Only one event is emitted: `issue:updated` with payload `{ id, status }` — broadcast to all clients when an authority updates an issue's status
- No authentication on socket connections

## 9. API Reference

### Auth Routes — `/api/auth`

```
POST   /api/auth/signup
Authorization: None (public)
Body: { email, password }
Returns: { token, user: { id, email, role } }
Notes: role is ALWAYS "user". Authority accounts cannot be created here.

POST   /api/auth/login
Authorization: None (public)
Body: { email, password }
Returns: { token, user: { id, email, role } }
```

### Issue Routes — `/api/issues`

```
POST   /api/issues
Authorization: Bearer <token> (any authenticated user)
Body: multipart/form-data — { title, description, category, locationText,
      latitude?, longitude?, image? }
Returns: Created issue document (populated with userId.email)

GET    /api/issues/my
Authorization: Bearer <token> (any authenticated user)
Returns: Array of issues belonging to the logged-in user, sorted by createdAt desc

GET    /api/issues/stats
Authorization: Bearer <token> + role=authority
Returns: { total, byStatus: { pending, in_progress, resolved }, byCategory: { Road, ... } }

GET    /api/issues
Authorization: Bearer <token> + role=authority
Query params: ?category=Road (optional), ?status=pending (optional), ?search=text (optional)
Returns: Filtered array of all issues, sorted by createdAt desc

PATCH  /api/issues/:id/status
Authorization: Bearer <token> + role=authority
Body: { status }  — must be one of: pending | in_progress | resolved
Returns: Updated issue document
Side effect: Emits Socket.io event "issue:updated" to all connected clients

GET    /api/health
Authorization: None
Returns: { status: "ok", timestamp }
```

## 10. Issue Reporting Workflow

### Path A — 4-Step Wizard (primary, at `/report`)

```
Citizen logs in
  ↓
Navigates to /report (or taps FAB on dashboard)
  ↓
Step 1 — StepCapture
  • Opens device camera (rear cam preferred on mobile via facingMode: 'environment')
  • OR selects image from gallery (file input, accepts image/*)
  • Image compressed client-side (max 1 MB, 1280px, JPEG 85% quality)
  • Preview shown with retake option
  ↓
Step 2 — StepLocation
  • navigator.geolocation.getCurrentPosition() called automatically on mount
  • If GPS granted: Nominatim reverse geocodes lat/lon → human-readable address
  • Draggable Leaflet marker shown — citizen can adjust exact pin position
  • If GPS denied or unavailable: manual text input shown
  • Skip option available (submits with empty lat/lon)
  ↓
Step 3 — StepDetails
  • Title (max 100 chars)
  • Category: pill grid on desktop (sm breakpoint), native select on mobile
  • Description (max 1000 chars)
  ↓
Step 4 — StepReview
  • Shows image thumbnail, category, title, location, description
  • AI Insights card runs mock analysis (see AI section)
  • "Submit Report" button → POST /api/issues (FormData)
  • On success: success animation + redirect to /dashboard after 2.8s
  ↓
Issue stored in MongoDB
  ↓
Visible in citizen's /dashboard and authority's /admin
```

### Path B — Quick Report Form (inline on `/dashboard`)

A collapsible `ReportIssueForm` component is also embedded on the `UserDashboard` page as an accordion panel. This form:
- Accepts: title, description, category (pill grid), location text, GPS detect button, file upload
- Submits via `POST /api/issues`
- Does **not** include the camera viewfinder or AI insights
- Intended for quick desktop submissions

## 11. Authority Workflow

```
Authority user logs in (authority@civic.gov / Authority@123)
  ↓
Redirected to /admin (AuthorityRoute guard checks role === 'authority')
  ↓
Stats row: Total / Pending / In Progress / Resolved / Resolution % / Filtered count
  ↓
Category breakdown: animated progress bars per category (Road/Water/Electricity/Garbage/Other)
  ↓
View toggle (3 modes):
  │
  ├── LIST (default)
  │     Filter bar: free-text search + category dropdown + status dropdown + clear
  │     Issue grid (all issues or filtered subset)
  │     Each card has:
  │       • SLA badge: "New" (<24h), "Aging" (1–3d), "Overdue" (>3d)
  │       • "Location unavailable" note if issue has no GPS coordinates
  │       • Status update buttons: Pending / In Progress / Resolved
  │       • PATCH /api/issues/:id/status called on click
  │       • Socket.io "issue:updated" event emitted → all connected clients update instantly
  │
  ├── MAP
  │     Leaflet map with colour-coded markers per category
```

## 12. Image & Camera Functionality

### Camera — `hooks/useCamera.js`

- Uses `navigator.mediaDevices.getUserMedia()`
- Requests `facingMode: { ideal: 'environment' }` (rear camera on mobile)
- Resolution hint: 1280×720
- `captureFrame()` draws current video frame to Canvas and returns a JPEG Blob
- `closeCamera()` stops all MediaStreamTrack instances
- `isSupported` flag: false if `navigator.mediaDevices.getUserMedia` is not available
- Error handling: distinct messages for `NotAllowedError` (permission denied) and `NotFoundError` (no camera)

### Gallery Upload

- HTML `<input type="file" accept="image/*">` (hidden, triggered programmatically)
- Any image file up to 20 MB accepted at the input level
- Then compressed before passing to wizard state

### Image Compression — `utils/imageCompression.js`

- Wraps `browser-image-compression` library
- Default options: `maxSizeMB: 1`, `maxWidthOrHeight: 1280`, `useWebWorker: true`, `fileType: 'image/jpeg'`, `initialQuality: 0.85`
- Falls back to original file on compression error

### Backend Upload

- Route: `POST /api/issues` with `Content-Type: multipart/form-data`
- Multer stores files in `backend/uploads/`
- Filename: `issue-<timestamp>-<random>.<ext>`
- Max size enforced by Multer: **5 MB**
- Image served statically: `GET http://localhost:5000/uploads/<filename>`
- URL stored in `Issue.imageUrl` as `/uploads/<filename>`
- Image is **optional** — issues without images are fully supported

## 13. Location & Maps Functionality

### GPS Detection — `hooks/useGeolocation.js`

- Calls `navigator.geolocation.getCurrentPosition()` with `enableHighAccuracy: true`, timeout 10s, maxAge 60s
- On success: calls Nominatim reverse geocoding API
- Nominatim endpoint: `https://nominatim.openstreetmap.org/reverse?lat=...&lon=...&format=json&addressdetails=1`
- Nominatim User-Agent header set: `CivicWatch-App/2.0 (civic-issue-reporter)` (required by Nominatim usage policy)
- Falls back to raw coordinates string if Nominatim request fails
- On permission denied: sets error state; shows manual text input

### Map in Wizard — `LocationMapPreview.jsx`

- Small Leaflet map (200px tall) shown after GPS is obtained
- Single draggable marker at detected coordinates
- Dragging the marker updates `lat`/`lon` in wizard state
- Map re-centres when coordinates change (`RecenterMap` helper component)

### Map in Authority Dashboard — `AuthorityMap.jsx`

- Full Leaflet map (420px tall)
- **Only issues with both `latitude` AND `longitude` values are plotted** — issues without GPS are intentionally excluded
- Custom `L.divIcon` per category: coloured circle (orange/blue/yellow/green/purple)
- Click marker → Leaflet Popup with: title, description excerpt (80 chars), relative time
- Map default center: average of all plotted coordinates; falls back to India geographic center if no issues have GPS
- Issue count badge shows: "X geo-tagged · Y without location"
- Category colour legend shown below the header

### Tile Layer

- OpenStreetMap: `https://{s}.tile.openstreetmap.org/{z}/{x}/{y}.png`
- Attribution included in popup but `attributionControl` set to false on maps (attribution text still set on TileLayer)

### Leaflet Vite Fix — `utils/leafletSetup.js`

- Vite's asset bundling breaks Leaflet's default marker icon URLs
- Fix: deletes `_getIconUrl` and calls `L.Icon.Default.mergeOptions()` with CDN URLs from unpkg

## 14. Real-Time Functionality

**What's implemented:** One-directional real-time status push from server to all clients.

- When authority updates an issue's status (`PATCH /api/issues/:id/status`), the server emits `io.emit('issue:updated', { id, status })` to ALL connected Socket.io clients
- `useSocket.js` connects to the backend and listens for `issue:updated`
- `AuthorityDashboard.jsx` uses `useSocket` to update the TanStack Query cache in real time and show a toast notification
- `UserDashboard.jsx` does **not** currently use `useSocket` — citizens do not receive real-time updates

**What's not implemented:**
- Per-room/per-user socket events
- Authenticated socket connections (token verification on connect)
- Citizens receiving real-time updates when their issue status changes
- New issue notifications to the authority

## 21. Known Limitations

1. **Local image storage** — uploaded images are stored on the server's local disk in `backend/uploads/`. This does not work with multiple server instances or deployments to serverless platforms. Images will be lost if the server is restarted on a cloud provider without persistent storage.

2. **No pagination** — `GET /api/issues` returns all issues. For large datasets, this will become slow.

3. **5 MB server upload limit vs. 1 MB client compression** — the client compresses to ~1 MB before upload, but the server accepts up to 5 MB. If someone bypasses the frontend, larger files can be uploaded.

4. **No token refresh** — JWT expires after 7 days; there is no refresh token mechanism. Users will be logged out and must re-login.

5. **Socket connections are unauthenticated** — any client can connect to the Socket.io server without a token. Status update events are broadcast to everyone regardless of role.

6. **Single authority account** — the seed script creates exactly one authority account. There is no UI or API to create additional authority accounts.

7. **Nominatim rate limiting** — the Nominatim public API has usage limits. For production use, a self-hosted Nominatim or a paid geocoding API should be used.
